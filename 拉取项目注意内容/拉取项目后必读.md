# 拉取项目后必读

> 换了电脑、重装了系统、或者重装了 OpenClaw 之后，按本文档从第 1 步走到第 5 步。
> 整个项目**不能只靠 `git clone` 就跑起来**——有一批东西在仓库外，必须单独恢复。

---

## 一、先认清：哪些东西不在仓库里

`git clone` 之后你会得到代码、脚本、文档，但**拿不到**下面这些。

| 缺失内容 | 在哪 | 为什么不在仓库 | 恢复方式 |
|---|---|---|---|
| **OpenClaw 的两个技能** | `~/.openclaw/workspace/skills/` | OpenClaw 只读这个目录，与项目目录平行，git 管不到 | 跑 `scripts\install_skills.py`（**最容易被忘，忘了技能完全不生效**） |
| **video-cleaner 运行环境** | `video-cleaner\.venv`（4.3G） | 数万个小文件，git 快照存储会让仓库爆炸 | 跑 `video-cleaner\setup_env.py` |
| **ffmpeg 便携版** | `video-cleaner\tools`（497M） | 二进制，单文件超 100MB | 同上脚本自动下载 |
| **LaMa ONNX 模型** | `video-cleaner\models\lama_fp32.onnx`（208M） | 超 GitHub 单文件 100MB 上限 | 同上脚本自动下载 |
| **LaMa GPU 权重** | `video-cleaner\models\big-lama.pt`（205M） | 同上，且公开源只有原始 `.ckpt` | **只能手工拷贝**（U 盘/网盘/旧机器） |
| **抖店登录态** | BrowserOS 浏览器的 profile | 是账号凭证，绝不能进仓库 | 浏览器里手动登录 `fxg.jinritemai.com` |
| **LM Studio 模型** | LM Studio 自己的模型目录 | 与项目无关 | 在 LM Studio 里下载 `qwen3.5-9b` |
| 商品导出表 | `商品数据\*.xlsx` | 每日生成的数据 | 跑导出技能自动生成 |
| 下载的短视频 | `带货短视频\` | 体积大且可重新下载 | 跑流水线自动生成 |

**仓库里已经有的**（不用额外处理）：全部 Python 脚本、技能定义（`抖店管理工作流\skills\`）、
晓风插件源码（`插件\晓风运营插件-30.3.3\`）、5 个水印模板 PNG、全部文档。

## 二、五个步骤，按顺序做

### 第 1 步：装基础软件

| 软件 | 版本要求 | 说明 |
|---|---|---|
| Python | 3.13 | 装在 `D:\Install\Python\`（脚本里的路径写死了这个位置） |
| OpenClaw | 任意较新版本 | 首次启动会生成 `~/.openclaw/` |
| BrowserOS neo | — | 抖店操作全靠它，端口 9010 / 9110 |
| LM Studio | — | 加载 `qwen/qwen3.5-9b`，开本地服务（端口 1234） |

> ⚠️ **所有脚本都假设项目在 `D:\Data\DouDian`**。如果放在别处，
> 需要改 `scripts\*.py` 里的 `PROJ` / `ROOT` 常量（每个脚本顶部都有）。

### 第 2 步：恢复 OpenClaw 技能

```bat
D:\Install\Python\python.exe D:\Data\DouDian\scripts\install_skills.py
```

它把 `抖店管理工作流\skills\` 下的两个技能复制到 `~/.openclaw/workspace/skills/`：
`doudian-export`（商品导出）和 `compass-video-rank`（短视频榜下载/去水印/清理）。

装完**必须重启 OpenClaw**，技能定义是启动时加载的。

### 第 3 步：恢复去水印环境

```bat
D:\Install\Python\python.exe D:\Data\DouDian\video-cleaner\setup_env.py
```

幂等脚本，自动完成：建 venv → 装依赖 → 下 ONNX 模型（带 SHA256 校验）→ 下 ffmpeg → 环境自检。
约 10 分钟，大半时间花在 torch（2.6GB）。

**然后手工补 `big-lama.pt`**（没有也能跑，会退回 CPU，慢 35 倍）：

```
把旧机器的 video-cleaner\models\big-lama.pt 拷到同一位置
```

### 第 4 步：加载晓风运营插件

插件源码在仓库里（`插件\晓风运营插件-30.3.3\`），但浏览器不认识它，要手动加载：

1. 打开 BrowserOS，地址栏进 `chrome://extensions/`
2. 右上角开「开发者模式」
3. 点「加载未打包的扩展程序」，选 `D:\Data\DouDian\插件\晓风运营插件-30.3.3`

或者用脚本自动加载（需要 BrowserOS 正在运行）：

```bat
powershell -ExecutionPolicy Bypass -File D:\Data\DouDian\scripts\fix_extension.ps1
D:\Install\Python\python.exe D:\Data\DouDian\scripts\reload_page.py
```

> ⚠️ 插件源目录**不能移动或改名**，未打包扩展按路径引用，路径一变立刻失效。

### 第 5 步：启动服务并验证

启动顺序：**LM Studio（加载模型）→ BrowserOS → 双击 `D:\Data\DouDian\启动OpenClaw.bat`**

然后逐项验证：

```bat
:: 1) OpenClaw 网关，应显示 Runtime: running
openclaw gateway status

:: 2) LM Studio 模型，应返回 qwen/qwen3.5-9b
curl -s http://127.0.0.1:1234/v1/models

:: 3) 去水印环境，五项应全绿
D:\Install\Python\python.exe D:\Data\DouDian\video-cleaner\setup_env.py

:: 4) 晓风插件是否注入（先打开榜单页，itemPers 应等于当前页商品数）
D:\Install\Python\python.exe D:\Data\DouDian\scripts\probe_page.py
```

## 四、最容易踩的四个坑

**1. 忘了装技能，OpenClaw 说“没有下载脚本”**
OpenClaw 只看 `~/.openclaw/workspace/skills/`。跑 `install_skills.py` 并重启。

**2. 重启电脑后插件丢了，抓到 0 个商品**
未打包扩展不会自动恢复。症状：页面正常显示商品列表，但 `probe_page.py` 的 `itemPers` 为 0。

**流水线已自动处理**，顺序是这样（顺序本身很关键，别随意调整）：

```
⓪.5  ensure_extension --load    只把扩展加载好，不碰页面
①    打开榜单页                  新页面会自动注入，无需刷新
①.5  ensure_extension --check   只验证，不修复
②    抓取
```

**为什么是这个顺序**：如果先打开页面再修插件，修完必须刷新才能注入；
而**刷新会把榜单 tab 从「短视频榜」重置回「总榜」**——这时抓取拿到的是商品榜数据，
`videourls` 属性为空，表现为「200 个商品 / 0 个视频」，最后下载 0 个文件。
这是 2026-10-25 实际踩过的坑，改顺序后才正常。

**一眼判断抓的是哪个榜**：看表头。
出现「排名 / 商品 / 店铺名称 / 用户支付金额 / 点击次数 / 成交件数」= 商品榜，抓不到视频。

单独排查时按需选择：

```bat
:: 只确保扩展加载（不碰页面、不刷新，可随时安全执行）
D:\Install\Python\python.exe D:\Data\DouDian\scripts\ensure_extension.py --load

:: 只检查页面是否注入（不刷新）
D:\Install\Python\python.exe D:\Data\DouDian\scripts\ensure_extension.py --check

:: 检测 + 修复（会刷新！刷新后 tab 重置，需重跑 compass_video_rank.py）
D:\Install\Python\python.exe D:\Data\DouDian\scripts\ensure_extension.py
```

三种情况的判定与退出码（0 表示正常）：

| 情况 | 判断依据 | 动作 | 退出码 |
|---|---|---|---|
| 插件源缺失（真没装） | `插件\晓风运营插件-30.3.3\manifest.json` 不存在 | 提示 `git checkout -- 插件/` | 2 |
| 源在但被拦截 | 页面 `itemPers` 为 0 | `--load` 只加载；默认模式加载+刷新+复检 | 5 / 6 |
| 已生效 | `itemPers` > 0 | 直接通过 | 0 |

服务没起来时（BrowserOS / MCP 未运行）退出码 3，并明确提示先启动浏览器。

**额外排查工具**：`probe_attrs.py` 可以打印插件在 `<p itemid>` 上注入了哪些属性，
其中 `videourls` 是否为空，直接决定能不能抓到视频。

**3. 命令行 curl 本地地址返回 502**
是环境代理拦截，不是服务坏了。加 `NO_PROXY=localhost,127.0.0.1`，或 `curl --noproxy "*"`。

**4. 隔夜复用旧链接，全部 403**
抖音 CDN 直链带签名，几小时就过期。必须重跑 `fetch_rank.py` 重新抓，
不能直接拿旧的 `商品数据\短视频榜单_抓取.json` 下载。

## 五、判断“任务真的完成了”的方法

本地模型（Qwen3.5-9B）会过度自信，脚本失败也常说“已完成”。**只看文件，不看它的话**：

| 检查项 | 说明 |
|---|---|
| `带货短视频\_下载清单.json` | 存在且时间戳是刚才 → 下载真跑了 |
| `商品数据\短视频榜单_抓取.json` 的 `fetched_at` | 是今天 → 抓取真跑了 |
| `带货短视频\商品名\` 里的 mp4 数量和体积 | 每条几 MB 到几十 MB，若只有几百 KB 或 4.5 秒，说明编码失败 |
| 成品文件名带 `_去水印版` | 后缀对 → 走的是去水印流程 |

### 推送失败的排查（本次实际遇到）

**症状**：

```
fatal: unable to access 'https://github.com/li1821023409/DouDian.git/':
schannel: failed to receive handshake, SSL/TLS connection failed
```

**原因**：GitHub 直连被阻断，TCP 能连上但 TLS 握手被切断。Git 没有走代理就会这样。
`schannel` 是 Windows 自带的 TLS 实现，git for Windows 默认用它，这个报错不代表证书有问题。

**先确认代理可用**：

```bat
:: 看代理端口是否在监听（Clash 默认 7897）
netstat -ano | findstr ":7897"

:: 看代理能否连通 GitHub，返回 200 Connection established 即正常
curl -I -x http://127.0.0.1:7897 https://github.com
```

**再确认 git 用了代理**：

```bat
git config --global --get http.proxy
:: 应输出 http://127.0.0.1:7897
```

**临时强制走代理推送**（不改配置）：

```bat
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin master
```

**如果 GUI 工具推送失败但命令行成功**：TortoiseGit / VS Code 的 Git 面板可能不读
`~/.gitconfig` 的全局代理，或者用了自己内置的 git。遇到这种情况直接用命令行推，
或者在 GUI 的网络设置里单独填代理。本次就是这个原因——命令行走代理 fetch 正常
（退出码 0），而 GUI 报了 SSL 握手失败。

> ⚠️ **别把代理写死在仓库配置里**（`git config http.proxy`，不带 `--global`），
> 那样换机器或换网络后会连不上，还得记得删。用 `--global` 或命令行临时指定。
