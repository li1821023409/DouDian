# 自动整理抖店数据（商品导出）

## ⚠️ 执行方式（最重要，先读这段）

**这个技能的全部工作都封装在 Python 脚本里。你的唯一任务是执行下面这条命令。**

```bash
D:/Install/Python/python.exe "{{PROJ}}/scripts/doudian_export.py" --target-dir "{{PROJ}}/商品数据" --with-slot
```

用 `bash` 工具执行这条命令，等待结束（约 40 秒），然后把输出里的
`RESULT_PATH=<路径>` 报给用户。**这就完成了。**

### 汇报方式（严格遵守，直接影响用户等待时间）

脚本跑完后，**只回一句话**，格式如下，不要加任何其他内容：

```
已导出：<文件名>（<商品数> 个商品）
路径：<RESULT_PATH 的值>
```

**禁止在脚本成功后做任何额外动作**：

- ❌ 不要再去 `ls` / `dir` 确认文件是否生成——脚本的 `RESULT_PATH` 就是结果
- ❌ 不要打开文件、读取表格内容或做任何数据统计
- ❌ 不要写总结、复盘、原理说明或"接下来建议"
- ❌ 不要重新执行脚本"以确保成功"

> **原因**：本地模型（Qwen3.5-9B）是推理模型，写一段长回复需要
> 大量 token 用于内部思考。实测生成一句 30 字的话要 9 秒、消耗 500 个
> 思考 token 且最终输出 0 字。导出已经完成的情况下，多写一段分析
> 会让用户白等 1–2 分钟，却没有任何实际价值。

### 绝对不要做的事

- ❌ **不要**自己调用 `browseros-neo__act` / `browseros-neo__snapshot` /
  `browseros-neo__tabs` 等浏览器工具去点「导出查询商品」「下载报表」按钮。
  脚本内部已经封装了全部浏览器操作，包括弹窗遮罩、ref 提取、标签页清理。
- ❌ **不要**自己尝试「先获取快照再用 act 点击」这类手工流程。
  手工操作极易陷入反复失败（实测出现过 8 项连续失败、上下文被压缩到 4.6k token）。
- ❌ **不要**因为脚本某一步报错就去改用浏览器工具绕过。先看报错内容。

脚本失败时，把原始报错读给用户，并指出对应处理建议（见下方「常见失败」）。

## 前置条件

1. **浏览器必须已登录抖店**（`fxg.jinritemai.com`）。登录态失效时脚本会明确报错。
2. **必须关闭「下载前询问每个文件的保存位置」**。
   Chrome/Edge：`设置 → 下载内容 → 关闭该开关`。
3. browseros-neo MCP 需在 `http://127.0.0.1:9010/mcp` 监听。
4. Python 解释器在 `D:\Install\Python\python.exe`（不要用 `python`，系统 PATH 里没有）。

## 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--target-dir` | 文件归档目录（必填） | — |
| `--with-slot` | 文件名追加时段（`_上午`/`_下午`/`_晚间`） | 关 |
| `--tab` | `onSale` 售卖中 / `all` 全部 / `offSale` 已下架 | `onSale` |
| `--keep` | 保留最新几份文件 | `2` |
| `--login-url` | 收藏夹里的抖店登录入口 | 已内置 |
| `--skip-login` | 跳过登录入口直接进后台 | 关 |
| `--timeout` | 等待后台生成报表的秒数 | `180` |
| `--no-clean` | 本次不清理旧文件 | 关 |
| `--keep-pattern` | 清理时的文件名匹配模式 | `*.xlsx` |
| `--keep-open` | 运行结束保留浏览器页面（调试用） | 关 |
| `--dry-run` | 只走到确认弹窗，不真正导出 | 关 |

用户如果要**导全部商品**，把命令改成加 `--tab all`；
如果要**先验证不导出**，加 `--dry-run`。其他情况一律用上面那条默认命令。

## 常见失败

| 报错 | 原因 | 处理 |
|---|---|---|
| `抖店登录态已失效` | 登录过期 | 让用户在浏览器里登录抖店，再重跑脚本 |
| `Download timed out after 60000ms` | 浏览器弹保存位置对话框 | 让用户关闭「下载前询问保存位置」 |
| `等待下载链接超时` | 抖店后台还没生成完 | 等几十秒后重跑 |
| `MCP 连接失败` | browseros-neo 没启动 | 确认 9010 端口有服务 |

遇到失败**如实报告给用户**，并给出上表对应的处理建议。
不要自行绕过、不要反复重试超过 2 次。

## 文件命名与清理

新下载的文件重命名为 **`<年月日><状态>[_<时段>].xlsx`**，例如
`20261017销售中_上午.xlsx`、`20261017销售中_晚间.xlsx`。

时段划分：12 点前 → `_上午`；12–18 点 → `_下午`；18 点后 → `_晚间`。

**清理规则**：每次导出成功后删除旧文件，按修改时间倒序保留最新 `--keep` 份
（默认 2，恰好对应每天早、晚各一份）。删除只匹配 `--keep-pattern`，
逐个打印文件名以便追溯。

清理是不可逆的删除。若目标目录混有需长期保留的文件，
需在命令上加 `--no-clean`。

## 输出数据规格

21 列，售卖中 162 个商品展开 SKU 后 3010 行：

```
商品ID | 商品名称 | 一级类目 | 二级类目 | 三级类目 | 四级类目 | 商品类型
| 商品分组 | 商家编码 | 商家SKU编码 | 规格ID（SKUID）| 商品规格
| 商品发货时间 | 商品价格 | 现货可售 | 预售库存 | 阶梯库存
| 销量 | 商品审核状态 | 商品链接 | 货号
```

注：刚提交导出后立刻下载，抖店后台可能还没生成完，行数会偏少
（曾出现 583 行 vs 3010 行）。若怀疑不完整，可隔几十秒重跑一次。

## 维护信息（仅在用户要求修改代码时才需要读）

脚本：`{{PROJ}}/scripts/doudian_export.py`，纯标准库，无需 pip 依赖。
（本技能目录只有这份 SKILL.md，脚本统一放在仓库 `scripts\`。）

内部流程为抖店的异步导出三段式：提交 → 后台生成 → 从「查看导出记录」页下载。

实现上已处理的坑（改代码前必读）：

- **页面归属**：browseros 中只有当前连接自己开的页面才带 attached session，
  复用他人 tab 会报 `has no attached session`。
- **标签页残留**：抖店「查看导出记录」会新开标签页；一次运行开 3 个页面
  （登录入口 / 商品管理 / 导出记录）。`main()` 的 `finally` 块统一清理。
- **弹窗遮罩**：导出弹窗遮罩会挡住「查看导出记录」，
  `close_export_dialog()` 按 Close → 取消 顺序两轮重试。
- **ref 提取**：表格快照中 `cell "下载报表"` 排在
  `link "下载报表" [ref=eN]` 之前，取 ref 必须同时匹配 `[ref=`。
- **snapshot 深度**：抖店侧边栏极深，`depth` 需 ≥30 否则表格被截断。
- **`run` 工具不适合下载**：单次上限 30 秒，而 `page.download` 本身可能超过；
  应用独立的 `download` 工具。

> **短视频榜单相关**（打开榜单页 / 下载带货短视频 / 去水印 / 删除本地视频）请走 `compass-video-rank` 技能。
