## 三、功能说明

### 3.1 核心功能

自动完成以下动作，无需人工干预：

1. **访问收藏夹的登录入口**（`--login-url`），刷新抖店登录态
2. 探测并确认登录有效性；若登录态失效会明确报错，而不是在页面上空等
3. 打开「商品管理」页面并切到**售卖中**标签
4. 点击「导出查询商品」
5. 在弹窗中确认导出（21 个报表字段）
6. 提交导出任务，等待抖店后台生成表格
7. 打开「查看导出记录」，下载生成的 xlsx
8. 搬运到归档目录并按规则重命名
9. 删除历史旧文件
10. **关闭本次打开的所有浏览器页面**，不留残留标签

### 3.2 浏览器标签页管理

脚本运行过程中会开多个页面，跑完后**自动全部关闭**，浏览器保持干净。

运行过程涉及的页面：

| 页面 | 说明 | 何时关闭 |
|---|---|---|
| 登录入口页 | 唤醒抖店会话 | 唤醒后立即关闭 |
| 商品管理页 | 执行导出操作 | 运行结束关闭 |
| 导出记录页 | 抖店会**新开标签页**，需切换过去下载 | 运行结束关闭 |

关闭逻辑写在 `finally` 块里，**成功或失败都会清理**（对比运行前后的页面列表，
只关本次新增的，不动你自己开的页面）。

调试时若想保留页面观察，加 `--keep-open`。

### 3.2 关于登录入口的实测说明

收藏夹里的抖店书签（`fxg.jinritemai.com/login/common/channel?...`）**实测行为**：

- 打开后停留在**抖店官网空壳页**，标题「抖店 | 分享优价好物 多元电商服务」
- 页面 `document.querySelectorAll('a')` 返回**空数组**，没有任何可点击链接
- **不会**自动跳转到商家后台

因此脚本的实际策略是：**先访问登录入口刷新会话，再直接导航到商品管理页 URL**。
两者配合工作——登录入口负责「唤醒」，商品管理 URL 负责「干活」。

脚本会在导航后检查页面是否出现「导出查询商品」按钮来判断登录态；
若页面显示登录/扫码/验证码，则直接报错提示需要重新登录。

### 3.2 文件命名规则

新下载的文件统一重命名为 **`<年月日><状态>[_<时段>].xlsx`**：

| 导出范围（`--tab`） | 加 `--with-slot`（定时任务启用） | 不加（手动单次） |
|---|---|---|
| `onSale` — 售卖中（默认） | `20261017销售中_上午.xlsx` | `20261017销售中.xlsx` |
| `all` — 全部 | `20261017全部_晚间.xlsx` | `20261017全部.xlsx` |
| `offSale` — 已下架 | `20261017已下架_下午.xlsx` | `20261017已下架.xlsx` |

**时段划分**：12 点前 → `_上午`；12–18 点 → `_下午`；18 点后 → `_晚间`。

> 每天导出两次时必须带 `--with-slot`，否则早 9 点和晚 21 点导出的
> 同一天文件会撞名，晚的那次会覆盖或顶掉早上的那份。

同一时段内重复运行时若文件名冲突，自动追加 `_HHMMSS`，不会覆盖已有文件。

### 3.3 旧文件清理规则

每次导出成功后自动清理历史文件：

- 按修改时间倒序，**保留最新 `--keep` 份**（默认 **2**，对应每天两次导出）
- 删除时逐个打印文件名，便于事后追溯
- ⚠️ **删除不可撤销**，详见第四节注意事项

## 四、使用方法

### 4.1 前置条件（必须满足）

| # | 条件 | 检查方式 |
|---|---|---|
| 1 | 浏览器已登录抖店 | 打开 `fxg.jinritemai.com` 确认能看到商品列表 |
| 2 | **关闭「下载前询问每个文件的保存位置」** | Chrome/Edge：设置 → 下载内容 → 关闭该开关 |
| 3 | browseros-neo MCP 在运行 | 浏览器访问 `127.0.0.1:9010` 有响应 |

> 条件 2 若未关闭，浏览器会弹出原生保存对话框，脚本会卡在
> `Download timed out after 60000ms` 失败。这是实测踩过的坑。
>
> 登录态失效时脚本会明确报错，提示用收藏夹入口重新登录，不会静默失败。

### 4.2 三种运行方式

#### 方式一：命令行手动执行（最直接）

打开 PowerShell，粘贴执行：

```powershell
cd D:\Data\DouDian\scripts
& "D:\Install\Python\python.exe" doudian_export.py --target-dir "D:\Data\DouDian\商品数据" --with-slot
```

正常耗时约 **40 秒**，成功时最后一行输出：
```
RESULT_PATH=D:\Data\DouDian\商品数据\20261017销售中_晚间.xlsx
```

> 手动执行时也建议带 `--with-slot`，与定时任务产出的文件名保持一致。

#### 方式二：OpenClaw 网页界面里用自然语言触发

1. 浏览器打开 `http://127.0.0.1:18789`
2. 在对话框直接说：

   > 帮我导出抖店售卖中的商品数据

3. OpenClaw 会执行本工作流的 Python 脚本（约 40 秒完成）。

> ⚠️ **重要**：OpenClaw 的正确行为是**执行脚本**，不是自己用浏览器工具
> 一步步点「导出查询商品」「下载报表」。手工操作会反复失败
> （实测出现过 8 项连续失败、上下文被压缩），且耗时数倍于脚本。
>
> 若发现 OpenClaw 绕开脚本去手工操作，说明技能说明或用户偏好文件
> 被改坏了，需恢复为「有现成脚本时一律跑脚本」的规则。

#### 方式三：定时自动运行（已配置）

**当前状态：已启用**

| 项目 | 值 |
|---|---|
| 任务名称 | 抖店数据导出-每日 |
| 任务 ID | `d1665266-442b-44ca-a20b-82166041a09d` |
| 执行时间 | **每天 09:00 和 21:00** |
| cron 表达式 | `0 9,21 * * *` |
| 时区 | `Asia/Shanghai` |
| 产出文件名 | `YYYYMMDD销售中_上午.xlsx` / `YYYYMMDD销售中_晚间.xlsx` |
| 保留份数 | 2（早、晚各一份） |

**定时任务由 Gateway 驱动**，只要 OpenClaw 在运行就会按时触发，无需电脑开机状态下有人值守。

常用管理命令：

```powershell
# 查看所有定时任务
openclaw automations list

# 立即手动触发一次（测试用，不等定时）
openclaw automations run d1665266-442b-44ca-a20b-82166041a09d

# 查看运行历史（含每次的完整输出）
openclaw automations runs d1665266-442b-44ca-a20b-82166041a09d

# 临时停用
openclaw automations disable d1665266-442b-44ca-a20b-82166041a09d

# 恢复启用
openclaw automations enable d1665266-442b-44ca-a20b-82166041a09d

# 彻底删除
openclaw automations rm d1665266-442b-44ca-a20b-82166041a09d
```

**修改执行时间**：

```powershell
openclaw automations edit d1665266-442b-44ca-a20b-82166041a09d --cron "0 8,20 * * *"
```

常用 cron 表达式：

| 表达式 | 含义 |
|---|---|
| `0 9,21 * * *` | 每天 09:00 和 21:00（当前配置） |
| `0 9 * * *` | 每天 09:00 |
| `30 8,20 * * *` | 每天 08:30 和 20:30 |
| `0 9 * * 1` | 每周一 09:00 |
| `0 9 1 * *` | 每月 1 号 09:00 |

**重建定时任务**（如需改导出范围为「全部商品」）：

```powershell
openclaw automations rm d1665266-442b-44ca-a20b-82166041a09d

openclaw automations add "抖店数据导出-每日" `
  --command-argv '["D:/Install/Python/python.exe","D:/Data/DouDian/scripts/doudian_export.py","--target-dir","D:/Data/DouDian/商品数据","--with-slot","--keep","2"]' `
  --command-cwd "D:/Data/DouDian/scripts" `
  --cron "0 9,21 * * *" --tz "Asia/Shanghai" `
  --best-effort-deliver `
  --description "每天09:00和21:00自动导出抖店售卖中商品数据"
```

> 注意：`--command-argv` 用 JSON 数组传参，路径分隔符统一用 `/`，
> 避免 Windows 反斜杠在 JSON 中被转义（写成 `\\` 会被解析成 `//`）。
> `--command` 与 `--command-argv` 只能二选一，不能同时使用。
> 加 `--best-effort-deliver`：没配 chat channel 时投递失败不再把任务判成 error。

### 4.3 参数说明

| 参数 | 说明 | 默认值 |
|---|---|---|
| `--target-dir` | 文件归档目录（**必填**） | — |
| `--tab` | 导出范围：`onSale` 售卖中 / `all` 全部 / `offSale` 已下架 | `onSale` |
| `--with-slot` | 文件名追加时段（`_上午`/`_下午`/`_晚间`），一天多次导出时必加 | 关闭 |
| `--login-url` | 收藏夹里的抖店登录入口 URL | `https://fxg.jinritemai.com/login/common/channel` |
| `--skip-login` | 跳过登录入口，直接进商品管理页（更快） | 关闭 |
| `--keep` | 归档目录保留最新几份文件 | `2` |
| `--timeout` | 等待抖店后台生成表格的秒数 | `180` |
| `--no-clean` | 本次**不**清理旧文件 | 关闭 |
| `--keep-pattern` | 清理时匹配的文件名模式 | `*.xlsx` |
| `--keep-open` | 运行结束保留浏览器页面（调试用） | 关闭 |
| `--dry-run` | 只走到确认弹窗，不真正导出 | 关闭 |

### 4.4 常用示例

```powershell
# 默认：走登录入口 → 导出售卖中商品 → 文件名带时段 → 保留最新 2 份
python doudian_export.py --target-dir "D:\Data\DouDian\商品数据" --with-slot

# 浏览器已登录时跳过登录入口，更快

# 换用你自己的登录书签
python doudian_export.py --target-dir "D:\Data\DouDian\商品数据" --with-slot `
  --login-url "https://fxg.jinritemai.com/login/common/channel?cbizId=xxx"

# 导出全部状态的商品
python doudian_export.py --target-dir "D:\Data\DouDian\商品数据" --with-slot --tab all

# 保留最近 7 份，便于回溯
python doudian_export.py --target-dir "D:\Data\DouDian\商品数据" --with-slot --keep 7

# 只探测不导出，确认页面元素是否正常
python doudian_export.py --target-dir "D:\Data\DouDian\商品数据" --dry-run

# 归档目录混有其他需保留文件时，跳过清理
python doudian_export.py --target-dir "D:\Data\DouDian\商品数据" --with-slot --no-clean
```

## 六、注意事项

### ⚠️ 1. 旧文件删除不可撤销

清理默认保留最新 **2** 份（对应每天两次导出），**其余 `.xlsx` 会被直接删除**。

若归档目录内混有需要长期保留的文件，运行时务必加 `--no-clean`，
或用 `--keep-pattern` 把匹配范围收窄（例如 `--keep-pattern "20261017*.xlsx"`）。

### ⚠️ 2. 行数偏少可能是后台未生成完

抖店导出是**异步任务**。刚提交就立刻下载，后台可能还在生成，
会拿到明显偏少的行数（实测出现过 583 行 vs 3010 行，同一商品集合）。

若发现行数异常，隔几十秒重跑一次即可。

### ⚠️ 3. 登录态会过期

抖店登录状态失效时，脚本会**明确报错**：

```
抖店登录态已失效。请先在浏览器中用收藏夹入口登录抖店，然后重新执行本工作流。
```

在浏览器里用收藏夹的抖店入口登录一次即可。

> **定时运行的特别注意**：如果登录态过期，定时任务每天都会失败。
> 建议每隔几天到 `http://127.0.0.1:18789` 的 Automations 页面看一眼运行历史，
> 或每周登录一次抖店保持会话活跃。

### ⚠️ 4. 定时任务依赖 OpenClaw 在运行

定时任务由 OpenClaw 的 Gateway 进程驱动。若 Gateway 未启动，
到点不会执行。可在任务列表中查看 Next 字段确认下次执行时间是否正常推算。

### ⚠️ 5. 运行历史里的 "not delivered" 不代表失败

本任务未配置通知渠道（企业微信/邮件等），因此每次运行结束会显示
`ok (not delivered)`。**只要 `status` 是 `ok` 且导出目录出现新文件，
就代表执行成功**，可以忽略投递状态。

### ⚠️ 6. 不要卸载或移动 Python 目录

工作流依赖 `D:\Install\Python\python.exe`。若移动或删除该目录，
定时任务和手动执行都会报「系统未安装 Python 环境」。

如需安装第三方包，用这套 Python 的 pip：

```powershell
& "D:\Install\Python\python.exe" -m pip install 包名
```

pip 已配置清华镜像源（`pip.ini`），国内网络下速度较快。

## 七、常见问题排查

| 现象 | 原因 | 解决办法 |
|---|---|---|
| **OpenClaw 不跑脚本、自己在浏览器里点按钮** | 技能说明或用户偏好文件被改坏 | 恢复 技能定义-商品导出（副本）.md 的「执行方式」段与 USER.md 的脚本优先规则 |
| `has no attached session` | 复用了非本连接打开的标签页 | 脚本已处理：每次新开页面 |
| `is covered by ecom-g-drawer...` | 导出弹窗遮罩挡住按钮 | 脚本已处理：Close → 取消 两轮重试 |
| `Download timed out after 60000ms` | 浏览器弹出了保存位置对话框 | 关闭「下载前询问每个文件的保存位置」 |
| `抖店登录态已失效` | 登录过期 | 在浏览器用收藏夹入口重新登录 |
| `等待下载链接超时` | 导出记录尚未生成 | 增大 `--timeout`，或稍后重试 |
| 定时任务 `status: failed` | 通常是通知渠道未配置 | 看 `diagnostics.entries` 里的 `exitCode`，为 0 就是成功 |
| 定时任务到点没执行 | OpenClaw Gateway 未运行 | 启动 OpenClaw，确认任务列表 Next 时间正常 |

更多技术细节见 `技能定义-商品导出（副本）.md` 的「已踩过的坑」章节。

## 附：本地服务启动顺序

整套流程依赖三个本地服务，出问题按这个顺序查：

| 服务 | 端口 | 启动方式 | 是否开机自启 |
|---|---|---|---|
| LM Studio（模型 `qwen/qwen3.5-9b`） | 1234 | 打开 LM Studio → 加载模型 → 开启本地服务 | 由 LM Studio 设置决定 |
| browseros-neo（浏览器 MCP） | 9010 | 随 BrowserOS neo 启动 | 是 |
| **OpenClaw Gateway** | **18789** | 双击 `启动OpenClaw.bat`，**窗口要保持开着** | **否** |

`启动OpenClaw.bat` 在项目根目录 `D:\Data\DouDian\`，这是**唯一入口**（桌面不再放副本，避免两份不同步）。
**每次重启电脑后都需要手动双击**，因为没装成计划任务。

脚本启动前会做三项检查：

1. 18789 是否已被监听（避免重复双击）
2. `openclaw` 命令是否在 PATH 中
3. 1234（LM Studio）是否在跑——这是"网页能打开但一直转圈"最常见的原因

### 连不上时怎么查

```bash
# 网关状态：Runtime 应为 running
openclaw gateway status

# 模型服务（应返回 qwen/qwen3.5-9b）
curl -s http://127.0.0.1:1234/v1/models

# 浏览器 MCP（应返回 serverInfo）
curl -s -X POST http://127.0.0.1:9010/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1.0"}}}'
```

**注意**：命令行里 curl 本地地址前要设 `NO_PROXY=localhost,127.0.0.1`，
否则代理会返回 502，看起来像网关报错，实际只是代理拦截。

### 晓风插件丢失（每次重启电脑后都要检查）

晓风运营插件是**未打包扩展**，BrowserOS 重启后经常不自动加载。症状很典型：

- 榜单页面看起来正常，能看见商品列表
- 但 `<td p[itemid]>` 属性不存在 → `fetch_rank.py` 抓到 **0 个商品**
- 后续下载自然没有任何文件，目录是空的

**自检**（看 `itemPers`，正常应等于当前页商品数）：

```bat
D:\Install\Python\python.exe D:\Data\DouDian\scripts\probe_page.py
:: 正常: {"trs":11,"itemPers":10,...}
:: 异常: {"trs":11,"itemPers":0,...}
```

**一键修复**（两条都要跑，缺一不可）：

```bat
powershell -ExecutionPolicy Bypass -File D:\Data\DouDian\scripts\fix_extension.ps1
D:\Install\Python\python.exe D:\Data\DouDian\scripts\reload_page.py
```

第一条通过 CDP 9110 调 `Extensions.loadUnpacked` 重新挂载插件；
第二条刷新已打开的页面让 content script 注入——**不刷新不生效**。

修复成功标志：`fix_extension.ps1` 输出扩展 ID `oiinpblopagmgmihimfcfjpcdfimegme`。

> ⚠️ 插件源目录 `D:\Data\DouDian\插件\晓风运营插件-30.3.3` **不能移动或删除**，
> 未打包扩展按路径引用，路径一变立刻失效。
